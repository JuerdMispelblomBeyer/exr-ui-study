# Compute network — regional health overview

## Reference identity and evidence quality

- Source: `reference/ref-012__compute-network__dark-regional-health.jpg`.
- Type: direct dark infrastructure dashboard concept.
- Evidence: high for shell and regional status table; medium for hierarchy; low for genuine topology despite the title.

## Executive design reading

The design presents infrastructure in a polished dark chassis with generous
rounding, a centered navigation line, summary metrics, and a regional health
table. Its clearest lesson is calm status grouping; its greatest weakness is
calling a conventional dashboard a “topology.”

## Dimension analysis

### CR-AES-01 — Aesthetic and personality

**OBSERVATION** — A large rounded dark chassis floats against a purple-tinted
background.

**INTERPRETATION** — The screen feels polished and calm, but the mood is applied
to an otherwise standard infrastructure template.

**TRANSFERABLE PRINCIPLE** — Keep the calm dark chassis while deriving identity
from a truthful platform visualization rather than ambient color.

### CR-COMP-01 — Composition, grid, and alignment

**OBSERVATION** — Centered navigation, a horizontal KPI row, and a wide table
form symmetric stacked bands.

**INTERPRETATION** — The structure is easy to parse but category-led and weakly
task-oriented.

**TRANSFERABLE PRINCIPLE** — Replace the KPI-first stack with topology-first
composition and attach only the metrics needed for the current decision.

### CR-DEN-01 — Density and whitespace

**OBSERVATION** — Cards and table rows have generous padding relative to the
amount of information shown.

**INTERPRETATION** — The premium spacing lowers scanning efficiency.

**TRANSFERABLE PRINCIPLE** — Retain clear groups but compress routine state into
rows, glyphs, and aligned values.

### CR-TYPE-01 — Typography and hierarchy

**OBSERVATION** — A large page title and medium KPI values dominate; table copy
is compact and clean.

**INTERPRETATION** — Hierarchy is conventional and does not distinguish system
identity from marketing orientation.

**TRANSFERABLE PRINCIPLE** — Promote the actual selected node/fault and use mono
for hostnames, interfaces, versions, and timings.

### CR-COLOR-01 — Color and contrast

**OBSERVATION** — Purple supplies ambience while status uses small green/amber
cues on charcoal.

**INTERPRETATION** — Atmosphere consumes chromatic attention unrelated to user
meaning.

**TRANSFERABLE PRINCIPLE** — Let neutral surfaces create depth; reserve ExR
yellow and semantic hues for state, current context, and action.

### CR-GEO-01 — Geometry, borders, shadows, and surfaces

**OBSERVATION** — Large-radius panels nest inside an even larger-radius outer
shell with soft shadowing.

**INTERPRETATION** — Repeated rounding makes every region feel equally soft and
componentized.

**TRANSFERABLE PRINCIPLE** — Use one outer chassis radius, sharper internal
instrument geometry, and shared dividers.

### CR-IMG-01 — Imagery and iconography

**OBSERVATION** — No network diagram appears despite “Global Network Topology”;
regions are represented as a table.

**INTERPRETATION** — The screen labels a category instead of visualizing the
relationship it promises.

**TRANSFERABLE PRINCIPLE** — If a view is called topology, show nodes, links,
path state, and selectable connection evidence.

### CR-HIER-01 — Information hierarchy, interaction, and motion

**OBSERVATION** — Rows and filters imply selection; no cross-view relationship
or motion is shown.

**INTERPRETATION** — The flow is likely scan summary → inspect region row, with
limited causal context.

**TRANSFERABLE PRINCIPLE** — Support detect → locate → explain → act, keeping
the affected path visible throughout.

### CR-DIST-01 — Distinctive decisions and limits

**OBSERVATION** — The strongest stylistic features are violet glow and a large
rounded shell.

**INTERPRETATION** — These are common concept-dashboard traits and do not make a
recognizable product language.

**TRANSFERABLE PRINCIPLE** — Treat this as a baseline for calm grouping, then
reject its generic visual identity.

## Signature moves

| Move | Why it works | Transfer | Do not copy |

| Single outer chassis | Contains the product clearly | Stable ExR workbench frame | Oversized radius |
| Regional health rows | Supports comparative scanning | Compute-node/subsystem health rows | Geographic categories |

| Compact semantic badges | Makes state scannable | Label + icon + state color | Color-only dot |
| Centered top context | Keeps navigation visible | Robot/scope selector in chassis | Exact centered nav |

## Translation decisions

- **Borrow:** calm grouping, comparative health rows, contained chassis,
  readable dark contrast.
- **Ignore:** global-region content, KPI-first order, and “topology” label.
- **Brand-specific:** purple atmosphere and product typography.
- **Accidental:** concept crop may omit actual topology elsewhere.
- **Anti-patterns/limitations:** excessive radii and padding; generic SaaS
  symmetry; atmosphere without meaning; category screens; falsely visualized
  topology; limited diagnostic depth.
