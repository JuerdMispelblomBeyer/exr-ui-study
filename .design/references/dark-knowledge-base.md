## Executive design reading

This reference handles hierarchy through a professional multi-pane browser:
global tools, a tree, and a content surface coexist without becoming a tile
wall. Large tactile folder objects add a visual landmark inside a dense utility.

## Dimension analysis

### KB-AES-01 — Aesthetic and personality

**OBSERVATION** — A restrained dark utility surrounds unusually large,
dimensional folder objects.

**INTERPRETATION** — The product feels expert and systematic without being dry;
tactility is limited to content that benefits from recognition.

**TRANSFERABLE PRINCIPLE** — Add material character to a few system objects or
subsystem silhouettes while keeping diagnostic chrome precise.

### KB-COMP-01 — Composition, grid, and alignment

**OBSERVATION** — Narrow global rail, broader tree, and flexible content pane
increase in specificity from left to right.

**INTERPRETATION** — The layout externalizes the user’s drill-down path.

**TRANSFERABLE PRINCIPLE** — Let platform → subsystem → component/evidence
depth occupy adjacent panes when comparison and orientation must coexist.

### KB-DEN-01 — Density and whitespace

**OBSERVATION** — Navigation and tables are compact, while the folder stage
receives more breathing room.

**INTERPRETATION** — Density corresponds to task: scan tightly, recognize
objects broadly.

**TRANSFERABLE PRINCIPLE** — Use compact data rails beside a more spacious
system schematic rather than applying one spacing mode everywhere.

### KB-TYPE-01 — Typography and hierarchy

**OBSERVATION** — Typography is compact and consistent, with weight and tone
distinguishing headings, rows, and metadata.

**INTERPRETATION** — Type is functional but contributes little brand identity.

**TRANSFERABLE PRINCIPLE** — Retain compact sans typography for navigation and
use mono selectively for node IDs, interfaces, and timing.

### KB-COLOR-01 — Color and contrast

**OBSERVATION** — Most hierarchy comes from luminance; color is scarce.

**INTERPRETATION** — The content remains calm, though selected and actionable
states could be stronger.

**TRANSFERABLE PRINCIPLE** — Build the ExR shell in neutral layers and spend
yellow only on current scope, live path, and high-value action.

### KB-GEO-01 — Geometry, borders, shadows, and surfaces

**OBSERVATION** — Flat adjacent panes use hairlines; only content objects receive
obvious depth and rounded form.

**INTERPRETATION** — Surface hierarchy maps to meaning rather than universal
card elevation.

**TRANSFERABLE PRINCIPLE** — Keep chassis and evidence panes flat/inset; allow
selected system objects to lift or gain a contour.

### KB-IMG-01 — Imagery and iconography

**OBSERVATION** — Folder objects provide recognizable imagery; small icons
handle utilities and tree nodes.

**INTERPRETATION** — Object-scale visuals accelerate recognition but could
become decorative if not truthful.

**TRANSFERABLE PRINCIPLE** — Use simplified, accurate subsystem silhouettes or
camera stills as recognition anchors, never generic 3D tech props.

### KB-HIER-01 — Information hierarchy, interaction, and motion

**OBSERVATION** — Selection appears to flow from rail to tree to object/table;
expanders and rows advertise drill-down. Motion is not shown.

**INTERPRETATION** — Persistent context reduces reorientation during deep work.

**TRANSFERABLE PRINCIPLE** — Preserve ancestor scope while the engineer opens
details, and avoid ungrounded animation assumptions.

### KB-DIST-01 — Distinctive decisions and limits

**OBSERVATION** — The unusual move is dimensional folder imagery within a
dense, low-relief application shell.

**INTERPRETATION** — A single tactile content language differentiates an
otherwise familiar browser pattern.

**TRANSFERABLE PRINCIPLE** — Create an ExR-specific system-object language tied
to real hardware rather than copying folders or generic neumorphism.

## Translation decisions

- **Borrow:** progressive drill-down panes, task-dependent density, persistent
  ancestry, flat shell with one tactile content layer.
- **Ignore:** folder/file metaphors, document metadata, and exact iconography.
- **Brand-specific:** source folder sculptures and product taxonomy.
- **Accidental:** crop does not prove responsive or animated behavior.
- **Anti-patterns/limitations:** very small text; deep panes can crowd the
  workbench; decorative 3D objects can lower data density; selected state is
  understated.
