# Smart-home soft modules

## Reference identity and evidence quality

- Source: `reference/2d5752e87e30550c17339dbe32b213c6.jpg`.
- Type: direct light-interface composition.
- Evidence: high for component language and hierarchy; low for viewport shell
  and motion.

## Executive design reading

The reference makes a compact control surface approachable by combining a
strict two-column scaffold with soft containers and one oversized analogue
instrument. Unequal modules express function without losing family coherence.

## Dimension analysis

### HOME-AES-01 — Overall aesthetic and personality

**OBSERVATION** — Pale neutral space, broad corner radii, friendly line icons,
and a precise semicircular gauge coexist.

**INTERPRETATION** — The design feels domestic without becoming toy-like because
technical exactness remains inside the soft shell.

**TRANSFERABLE PRINCIPLE** — Use approachable outer geometry around precise
inner instrumentation when a technical product serves non-specialists.

### HOME-COMP-01 — Composition, grid, alignment

**OBSERVATION** — A device list occupies the left column; a dominant gauge and
nested scene controls share the right column on aligned edges.

**INTERPRETATION** — Overview and manipulation remain visible together, while
the gauge earns more area than secondary scenes.

**TRANSFERABLE PRINCIPLE** — Pair a stable object list with one enlarged selected
instrument; nest secondary states beneath instead of repeating equal cards.

### HOME-DEN-01 — Density and whitespace

**OBSERVATION** — Repeated device rows are compact; the gauge breathes; scene
cards use medium density.

**INTERPRETATION** — Density matches activity: scan many, control one, recall a
few presets.

**TRANSFERABLE PRINCIPLE** — Set density by user operation rather than by a
uniform component padding rule.

### HOME-TYPE-01 — Typography and type hierarchy

**OBSERVATION** — Labels use a compact sans with bold object names, muted usage
metadata, and a large central temperature value.

**INTERPRETATION** — Type moves from identity → state/value → supporting unit
without oversized page headings.

**TRANSFERABLE PRINCIPLE** — Let operational values dominate locally while
keeping shell labels compact.

### HOME-COLOR-01 — Color and contrast

**OBSERVATION** — Neutral whites/greys form the system; lime and blue appear in
small selected controls, while violet only marks the gauge.

**INTERPRETATION** — Accent allocation distinguishes focus from categories but
risks too many meanings. Greyscale remains readable.

**TRANSFERABLE PRINCIPLE** — Keep surface hierarchy neutral and assign the lead
brand accent to active state; use additional hues only for real semantics.

### HOME-GEO-01 — Geometry, borders, shadows, surfaces

**OBSERVATION** — Large rounded outer modules contain tighter pill rows and exact
ticks; shadows are broad and subtle.

**INTERPRETATION** — The radius ladder distinguishes container, control, and
instrument rather than applying one universal shape.

**TRANSFERABLE PRINCIPLE** — Define geometry by role: soft chassis, smaller
control radii, exact diagrams and scales.

### HOME-IMG-01 — Imagery and iconography

**OBSERVATION** — No photography is used; distinct line icons identify devices,
scenes, power, and navigation.

**INTERPRETATION** — Iconography supports scanning but remains subordinate to
names and values.

**TRANSFERABLE PRINCIPLE** — Use a consistent icon family for object type while
preserving text as the source of truth.

### HOME-HIER-01 — Information hierarchy, interaction, motion

**OBSERVATION** — Chevron rows, power toggle, radial pointer, scene selection,
and “See all” affordances are visible; motion is not shown.

**INTERPRETATION** — Direct control and disclosure are legible because each cue
is attached to its object. Motion implications are limited to gauge/toggle state.

**TRANSFERABLE PRINCIPLE** — Keep controls spatially attached to the object or
instrument they change and use motion only to confirm state.

### HOME-DIST-01 — Distinctive decisions and limits

**OBSERVATION** — The semi-analogue gauge and nested scene pair break an otherwise
familiar module system.

**INTERPRETATION** — Distinction is contextual rather than wholly unique; the
composition is stronger than the individual components.

**TRANSFERABLE PRINCIPLE** — Create one purpose-built instrument per major task
inside a restrained reusable shell.

## Translation decisions

- **Borrow:** overview/detail pairing, density by task, role-based radii, local
  value hierarchy, and attached controls.
- **Ignore:** user avatar, domestic devices, consumption units, and exact grid.
- **Brand-specific:** lime/blue combination and icon drawings.
- **Accidental:** square social-media crop and absent application chrome.
- **Anti-patterns/limitations:** too many pastel accents can dilute semantic
  color; pill rows may become repetitive; soft elevation must not reduce data
  contrast in dense engineering screens.
