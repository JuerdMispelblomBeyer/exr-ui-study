# Visual language

Use this document to turn product meaning into a recognizable formal system.
A visual language is a small grammar of repeated decisions, not a mood board,
color palette, or collection of trendy effects.

## 1. Write the visual thesis

Complete this sentence before building:

> This interface should feel like **[specific designed object or experience]**
> because the user must **[job/decision]** under **[conditions]**.

Good theses imply spatial and material decisions:

- “A calm diagnostic bench that brings one failing dependency into focus.”
- “An editorial research atlas where evidence is browsed, compared, and cited.”

Weak theses merely name adjectives:

- “Clean, modern, premium.”
- “Futuristic but friendly.”

## 2. Diverge before converging

When the user has not selected a direction, propose at least two routes that
change the spatial idea:

- object-first: one live object with attached evidence and controls;
- relationship-first: a topology, timeline, flow, or comparison field is the
  main surface;
- task-sequence: the composition follows a consequential progression;
- editorial-focus: one statement/image/instrument dominates while compact
  plates supply evidence;
- continuous-workbench: several instruments share axes and boundaries rather
  than becoming isolated cards.

Do not count light/dark, different accent colors, or different corner radii as
different routes. For each route name the user advantage, likely failure, and
design-system consequence. Choose explicitly; do not blend every route into one
indecisive screen.

## 3. Define character through opposites

Choose three to five paired constraints. The second term is explicitly
rejected:

| Intended | Not |
|---|---|
| instrumented | decorative |
| editorial | template-driven |
| spatial | category-card based |
| restrained | empty |
| tactile | skeuomorphic |

Resolve contradictions. “Dense and calm” can mean strict alignment, selective
detail, and quiet chrome. It cannot mean filling every region with small text.

## 4. Create a visual syntax

Define one decision for each layer:

| Layer | Operational question |
|---|---|
| Silhouette | What outer shape makes the product recognizable at thumbnail size? |
| Navigation | How does location belong to the product rather than sit beside it? |
| Field | Is the main surface continuous, segmented, layered, scrolling, or spatial? |
| Dominant object | What one object or relationship earns the largest area? |
| Module grammar | How do modules differ by purpose rather than category label? |
| Edge grammar | Which stroke, contour, overlap, bracket, crop, or shadow defines ownership? |
| Data grammar | How are current, historical, selected, uncertain, and comparative data distinguished? |
| Interaction marks | What visible cues imply real selection, manipulation, or disclosure? |
| Image grammar | What kind of imagery appears, at what scale, and with what relationship to data? |
| Motion grammar | What changes position, focus, or emphasis, and why? |

## 5. Choose two or three signature moves

A signature move must be:

- tied to a real product behavior or content relationship;
- repeatable in several contexts without becoming decoration;
- visible in greyscale;
- compatible with existing components and variables;
- uncommon enough to give the product identity.

Examples include a persistent evidence rail, a continuous instrument field,
object-attached annotations, a selected path that opens an inspector, or an
editorial scale contrast between one dominant statement and compact metadata.
“Large rounded cards” and “soft gradient” are not signatures.

## 6. Build a small motif budget

Use at most:

- one dominant silhouette;
- two or three signature moves;
- one edge/elevation grammar;
- one radius ladder;
- one accent behavior;
- one primary and one supporting imagery mode.

Novelty diluted across ten unrelated effects reads as generated noise.

## 7. Distinctiveness tests

Run these before polishing:

1. **Thumbnail:** at 15–20% scale, can the composition be recognized?
2. **Greyscale:** without brand color, do silhouette and hierarchy remain?
3. **Swap test:** if another SaaS logo replaced the current logo, would the
   design still look product-specific? If yes, strengthen the product grammar.
4. **Purpose test:** can every signature move be explained through user work?
5. **Family test:** can a second screen use the same grammar without repeating
   the first screen's exact layout?

Record failures as direction changes, not polish tasks.
