# Composition

Composition is the deliberate organization of masses, relationships, and
negative space across the viewport. It must emerge from the task, not from a
default dashboard recipe.

## Read the silhouette

At thumbnail scale, trace only:

- outer chassis and navigation mass;
- dominant content mass;
- main horizontal/vertical axes;
- interruptions, overlaps, and continuations;
- dense and sparse zones.

A strong composition has an explainable silhouette. “Sidebar, title, KPI row,
card grid” is a template description, not an explainable product composition.

## Composition tests

### Dominant-object test

Name the object or relationship the user came to inspect. Estimate whether its
area, position, and contrast match its importance. If a page-wide frame devotes
more visual mass to chrome, empty headers, or summaries than the actual work,
recomposition is required.

### Relationship test

Inspect whether related information shares axes, boundaries, connectors, or
spatial continuity. Proximity alone is not enough when separate cards imply
independent objects.

### Density-rhythm test

Mark each region sparse, medium, or dense. A strong screen intentionally
alternates them: orientation is usually sparse; manipulation focused; evidence
dense. Uniform density produces fatigue; uniform emptiness wastes the viewport.

### Asymmetry test

Symmetry is acceptable only when the task compares equals. Otherwise, use
controlled asymmetry, scale contrast, continuation, or cropping to express the
actual priority. Random offset is decoration, not composition.

### Viewport-economy test

Count how much of the first viewport directly supports orientation, decision,
action, or evidence. Flag ceremonial headers, duplicated labels, ornamental
margins, and low-information oversized modules.

## Card-dependency audit

For every rounded container, ask:

1. Does it represent a real object, temporary layer, or actionable boundary?
2. Does separation improve comprehension or only make the layout easy to build?
3. Could the information share a continuous work surface, axis, topology, or
   table instead?
4. Does its elevation differ because its behavior differs?

If several containers have identical anatomy and no independent behavior,
merge them. Vary span, depth, and density only when the information role varies.

## Failure patterns and corrections

| Failure | Why it matters | Correction | Desired visual outcome |
|---|---|---|---|
| Equal card grid | Flattens unequal information and looks templated | Promote the task's dominant instrument; merge supporting modules into aligned evidence fields | One dominant composition with subordinate evidence |
| Repetitive section bands | Makes every screen feel like the same page with relabeled content | Let each task define its main spatial object while preserving edge/type grammar | Family coherence without template sameness |
| Excessive symmetry | Removes tension and priority | Break symmetry at the dominant relationship; keep secondary alignments disciplined | Intentional directional flow |
| Arbitrary overlap | Adds fashion without ownership | Attach floating layers to selection, transient action, or detail disclosure | Depth communicates behavior |
| Oversized empty modules | Creates false importance and poor information economy | Reduce the module, increase meaningful evidence, or remove it | Area matches decision value |
| Dense wall of controls | Obscures the current task | Separate manipulation from evidence and disclose secondary controls contextually | Clear operational focus |
| Decorative connector lines | Pretends relationships without encoding them | Encode direction, dependency, state, grouping, or remove the lines | Every connector answers a relationship question |

## Screen-family critique

Compare sibling screens at thumbnail scale. They should share a visual grammar,
not an identical skeleton. Report:

- what composition changes because the task changes;
- what signature geometry, edge, type, and interaction behavior remains;
- which screen is merely a repeated template;
- which exception appears accidental rather than purposeful.

Prioritize composition before component polish. A wrong dominant mass cannot
be repaired by better shadows, radii, or icon alignment.
