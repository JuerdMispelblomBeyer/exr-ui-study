# Visual hierarchy

Hierarchy is the order in which meaning becomes available. It is not a list of
font sizes and it is not automatically created by putting a large title at the
top.

## Inspection passes

### Five-second read

Record, without zooming:

1. the first element seen;
2. the state or event understood next;
3. the primary action or investigation path;
4. the most important element that was missed.

Compare that order with the user's actual decision. If they differ, hierarchy
has failed even when every label is readable.

### Thumbnail test

At 15–20% scale, expect one dominant mass, one supporting path, and quiet
context. If five cards remain equally prominent, the layout has categories but
no visual argument.

### Greyscale and blur test

Mentally remove hue and blur fine detail. Check whether scale, position,
contrast, density, enclosure, and depth still express the correct order. If
brand color is the only cue, the hierarchy is brittle.

## Diagnose the channel

For each competing or invisible element, identify the channel causing it:

| Channel | Failure | Corrective move | Desired outcome |
|---|---|---|---|
| Scale | Several large blocks compete | Reduce subordinate mass or enlarge the task's dominant object | One unmistakable first read |
| Position | Critical state is peripheral | Move it into the primary scan path or attach it to its affected object | State and object are understood together |
| Contrast | Chrome outshouts content | Lower chrome contrast; concentrate contrast at evidence/action | Interface framing recedes |
| Density | Every region has equal detail | Create sparse orientation and dense evidence zones | Eye knows where to pause and where to inspect |
| Enclosure | Every item receives a box | Merge related evidence into a continuous field | Relationships become stronger than categories |
| Depth | All surfaces float equally | Flatten persistent surfaces; elevate selection/temporary layers only | Depth explains ownership and state |
| Type | Labels and values share weight | Separate roles by scale, weight, case, and rhythm | Values, labels, and guidance read in order |
| Color | Accent is everywhere | Reserve accent for current datum, action, or exceptional state | Accent regains authority |

## Common hierarchy defects

- **Header tax:** an oversized greeting/title consumes prime space while the
  user's decisive state begins below the fold. Compress the header into
  context chrome and move operational content upward.
- **KPI democracy:** equal metric cards imply equal importance. Let the current
  condition or anomaly dominate; group the rest as supporting evidence.
- **Alert without ownership:** a warning banner is visually loud but detached
  from the object that caused it. Attach state to the affected object and keep
  global escalation secondary.
- **Action camouflage:** the primary action uses the same treatment as filters
  or secondary links. Give it a unique semantic and spatial role, not merely a
  brighter fill.
- **Uniform label/value pairs:** repeated component anatomy creates a flat
  rhythm. Vary presentation according to decision importance and evidence type.

## Reporting hierarchy criticism

Name the current and desired scan order. For example:

> The four summary tiles win before the degraded network path, so the user
> reads totals before cause. Collapse the summaries into a quiet status strip
> and enlarge the selected path with the failed hop attached. The corrected
> screen should read degraded route → affected node → supporting metrics.

“Improve hierarchy” without this evidence and desired order is invalid.
